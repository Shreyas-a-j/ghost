# Canonical schema v1

All canonical state lives under `.ghost/`. Every JSON document carries
`schema_version: 1`. Version bumps require a migration function and a
rollback-compatible backup before the first write.

## Layout

```text
project/
  .ghost/
    config.toml
    project.json
    state.json
    answers.json
    generated-manifest.json
    dev.pid                 # runtime, ignored
    dev.log                 # runtime, ignored
    tasks/<id>.json         # Phase 3
    decisions/<id>.md       # reserved
    evidence/<run-id>.json  # Phase 4
    events.jsonl            # Phase 3
    handoff.json            # Phase 3
  AGENTS.md                 # OpenCode and/or Codex
  CLAUDE.md                 # Claude Code
  .opencode/commands/       # OpenCode only
  .claude/commands/         # Claude Code only
```

## `config.toml`

Static selection written by Ghost. It intentionally contains no secrets.

```toml
# Generated by ghost. Edit .ghost/answers.json and run `ghost regen`.
schema_version = 1
profile = "normal"        # normal | hackathon
adapters = ["opencode"]   # opencode | claude | codex; ordered, deduplicated
```

`adapters` is the selection used for the last generation and the default for
`ghost regen`. Passing `--adapter` explicitly replaces it. An unknown name is
rejected before any file is written.

## `project.json`

Repository facts captured without modifying the repository.

```json
{
  "schema_version": 1,
  "name": "orbit",
  "profile": "normal",
  "stack": "rust",
  "languages": ["rust"],
  "manifests": ["Cargo.toml"],
  "run_command": "cargo run",
  "git": {
    "revision": "f428c36...",
    "branch": "main",
    "dirty": false
  },
  "created_at": "2026-11-19T12:00:00+05:30",
  "updated_at": "2026-11-19T12:00:00+05:30"
}
```

Detection rules:

- Rust: `Cargo.toml`
- Python: `pyproject.toml`, `setup.py`, `Pipfile`, or `requirements.txt`
- TypeScript/Node: `package.json`
- Otherwise: `other`

Ordering prefers Rust, then Python, then Node. Multiple languages are recorded.

## `state.json`

Canonical workflow state. `STATE.md` renders the same sections for humans.

```json
{
  "schema_version": 1,
  "focus": ["Project initialized. Read `specs/00-overview.md` and run `/plan`."],
  "next": ["/plan", "/build task-board"],
  "done": [],
  "decisions": [],
  "blockers": [],
  "updated_at": "2026-11-19T12:00:00+05:30"
}
```

Rules:

- `focus` is 1-3 short lines.
- `next` holds actionable items without Markdown prefixes.
- `done` holds the most recent completed items.
- `decisions` records one-line decisions with reasons.
- `blockers` is empty when unblocked.

`ghost status` reads this file when present and falls back to `STATE.md` for v1
projects. `ensure_state` imports `STATE.md` before a generated view replaces it.

For adapters without project commands (currently Codex), initial `next` entries
name spec files directly instead of `/plan` and `/build <slug>`. Existing state
is never rewritten just because the adapter selection changes.

## `generated-manifest.json`

```json
{
  "schema_version": 1,
  "generated_at": "2026-11-19T12:00:00+05:30",
  "files": {
    "AGENTS.md": "<sha256>",
    "STATE.md": "<sha256>",
    "scripts/check.sh": "<sha256>"
  }
}
```

The manifest is the overwrite guard. It records the content Ghost last wrote,
not the current content on disk. See [GENERATED-FILES.md](GENERATED-FILES.md).

## `answers.json`

The v1 interview result remains the input model. It is not canonical task state.
Changes in v1 schema compatibility:

| Field | v1 | v1-compatible v2 |
| --- | --- | --- |
| `deadline` | required string | optional string; required only for `hackathon` |
| `demo_steps` | exactly 3 | 0-3 for `normal`, exactly 3 for `hackathon` |
| `must_haves` | 1-6 | 0-6 for `normal`, 1-6 for `hackathon` |

The JSON shape stays backward compatible: a v1 deadline string still parses.

## `tasks/<id>.json`

One record per task. Ids are `TASK-0001` upward and never reused.

```json
{
  "schema_version": 1,
  "id": "TASK-0001",
  "title": "Add refresh-token rotation",
  "status": "verification",
  "owner_agent": "opencode",
  "base_revision": "f428c36...",
  "references": ["src/auth.rs"],
  "acceptance_checks": ["cargo test"],
  "evidence_ids": [],
  "created_at": "2026-11-19T12:00:00+05:30",
  "updated_at": "2026-11-19T12:00:00+05:30"
}
```

States and the only allowed transitions:

| From | To |
| --- | --- |
| `backlog` | `ready`, `in_progress`, `cancelled` |
| `ready` | `in_progress`, `blocked`, `cancelled` |
| `in_progress` | `verification`, `blocked`, `cancelled` |
| `verification` | `done`, `in_progress`, `blocked`, `cancelled` |
| `blocked` | `ready`, `in_progress`, `cancelled` |
| `done`, `cancelled` | terminal |

`base_revision` is filled from Git HEAD when a task first starts. `references`
must be relative paths inside the project; `..`, absolute paths, and symlinks are
rejected by the same validator used for writes.

## `events.jsonl`

Append-only JSON Lines, one event per line. Every event has `schema_version`,
`timestamp`, and `kind`; task, revision, and metadata fields are optional.

```json
{"schema_version":1,"timestamp":"2026-11-19T12:00:00+05:30","kind":"task_transition","task_id":"TASK-0001","from":"backlog","to":"in_progress","metadata":{"owner":"opencode"}}
```

Kinds: `task_created`, `task_transition`, `handoff`, `resume`, `checkpoint`.
Values pass through redaction (control characters stripped, whitespace
collapsed, 200-character cap). Raw prompts, command output, and file contents
must not be written. Malformed lines are skipped on read so one damaged line
cannot block the CLI.

## `handoff.json`

```json
{
  "schema_version": 1,
  "created_at": "2026-11-19T12:00:00+05:30",
  "revision": "f428c36...",
  "branch": "main",
  "dirty": false,
  "state": { "schema_version": 1, "focus": [], "next": [], "done": [], "decisions": [], "blockers": [], "updated_at": "2026-11-19T12:00:00+05:30" },
  "tasks": [{"id": "TASK-0001", "title": "Add refresh-token rotation", "status": "verification"}],
  "evidence_ids": [],
  "note": "resume here"
}
```

`resume` compares `revision` with the current HEAD. A mismatch is reported as
stale and exits `2`; Ghost does not patch files or merge state automatically.

## Versioning and migration policy

- Readers reject an unknown future `schema_version` with a clear error.
- Writers always emit the current version.
- A migration reads the old document, transforms it in memory, writes a backup
  under `.ghost/backups/`, then atomically writes the new document.
- Migrations must be rollback-compatible for at least one release.
- `STATE.md` is never authoritative once `state.json` exists.

## Reserved for later phases

`decisions/<id>.md` remains reserved but no command writes it yet.
